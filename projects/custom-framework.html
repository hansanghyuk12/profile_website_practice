개요

본 프로젝트는 여러 트레이딩 전략을 일관되게 개발, 백테스트, 배포할 수 있는 모듈식 프레임워크입니다. 신호 생성, 포지션 관리, 리스크 관리 등 핵심 기능을 플러그인 아키텍처로 구현했으므로, 새로운 전략 추가 시 기존 코드의 수정을 최소화하면서도 재사용 가능한 구조를 유지합니다.

이 프레임워크를 통해 모멘텀, 평균 회귀, 변동성 거래 등 다양한 전략을 동일한 백테스팅 환경에서 테스트할 수 있으며, 성과 지표를 일관되게 계산하고 비교할 수 있습니다. 또한 향후 실시간 거래로의 전환도 용이하도록 설계되었습니다.

문제 정의

Challenge 1: 전략별 일관된 백테스팅

매 전략마다 독립적인 스크립트를 작성하면 인디케이터 계산, 데이터 처리, 성과 평가 로직이 중복되고, 실수가 발생하기 쉬웠습니다. 또한 전략 간 공정한 비교가 어려웠습니다.

Challenge 2: 포지션 관리의 복잡성

여러 자산 간 포지션을 동시에 관리하고, 포트폴리오 규제(최대 포지션 수, 최대 노출도 등)를 적용하는 로직이 복잡했습니다. 이를 일관되게 처리할 수 있는 통합 시스템이 필요했습니다.

Challenge 3: 성과 분석의 자동화

각 거래 후 손익, 누적 수익, 드로우다운, 샤프비율 등을 매번 수작업으로 계산하는 것은 비효율적이고 오류가 발생하기 쉬웠습니다.

Challenge 4: 전략 간 코드 중복

비슷한 기능을 여러 전략에서 반복 구현하게 되어, 버그 수정이나 성능 개선 시 모든 파일을 수정해야 했습니다.

아키텍처 & 접근 방법

🏗️ 핵심 아키텍처 (모듈식 구조)

1. SignalGenerator

추상 기본 클래스로 모든 신호 생성 로직을 정의. 매 자산마다 신호(Buy/Sell/Hold)를 출력합니다.

2. PositionManager

신호를 받아 실제 거래 신호로 변환. 포트폴리오 규제, 포지션 크기 제한 등을 적용합니다.

3. RiskManager

손절매, 익절매, 포트폴리오 레벨의 위험 제한을 관리합니다.

4. PerformanceAnalyzer

거래 결과를 수집하여 수익률, 샤프비율, 드로우다운, 윈율 등 모든 성과 지표를 자동 계산합니다.

5. Backtest Engine

위의 모든 컴포넌트를 오케스트레이션하여 일관된 백테스트 환경을 제공합니다.

① 신호 생성 인터페이스

모든 전략은 SignalGenerator 기본 클래스를 상속받아 generate() 메서드를 구현합니다:

class MomentumStrategy(SignalGenerator): def generate(self, data, lookback=20): momentum = data['close'].pct_change(lookback) return 1 if momentum > 0 else -1 if momentum < 0 else 0

② 통합 포지션 관리

모든 자산의 포지션 상태를 중앙에서 추적하고, 거래 전에 규제를 검사합니다:

  • 최대 동시 포지션 수 제한
  • 각 자산별 최대 포지션 크기 제한
  • 포트폴리오 전체 노출도 제한
  • 상관관계 기반 다양화 강화

③ 자동 성과 분석

백테스트 완료 후 PerformanceAnalyzer가 다음을 자동으로 계산합니다:

metrics = analyzer.compute_metrics() # 수익률, 샤프비율, 최대낙폭, 윈율, 프로핏팩터 등
